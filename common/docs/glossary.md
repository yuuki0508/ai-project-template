# 用語辞書 — __PROJECT_TITLE__

> **AIの命名がぶれる最大の原因はこの表の不在。** 業務用語が出てきたら、実装前にここへ追加する。
> 「種別」を `type` と `kind` と `category` に書き分けられると、後から検索も修正もできなくなる。

## 業務用語

| 日本語 | 識別子 | 種類 | 定義・注意点 |
|---|---|---|---|
| 案件 | `project` | テーブル | 1件の受注単位。見積前の引合も含む |
| 取引先 | `partner` | テーブル | 顧客・仕入先の両方を含む。`customer` は使わない |
| 締め | `closing` | 概念 | 月次で数値を確定させる処理。締め後は修正に履歴を残す |
| 論理削除 | `deleted_at` | カラム | NULL=有効。物理削除はしない |

## 表記の統一

| 使う | 使わない | 理由 |
|---|---|---|
| `partner` | `customer`, `client`, `torihikisaki` | 混在させない |
| `is_active` | `active_flg`, `enabled` | boolean は `is_` / `has_` 接頭辞 |
| `created_at` | `create_date`, `regist_datetime` | フレームワーク標準に合わせる |

## 迷ったときの原則

1. 顧客が実際に使っている言葉を日本語列にそのまま入れる（勝手に一般語へ言い換えない）
2. 識別子は英語の単数形・スネークケース。テーブル名だけ複数形
3. 一度決めたら変えない。変えるなら全置換して同じコミットでこの表も直す
